# Test Chat Lab: отклонение ответа и общий HTTP 500

## Наблюдение

В локальной лаборатории два события сохранились как FAILED / CONVERSATION_RESPONSE_UNAVAILABLE. Вызовы Qwen при этом завершились SUCCESS: это не подтверждённый отказ API. Проверка доступности HTML-страницы не проверяла отправку сообщения и была недостаточной.

При изолированном HTTP-воспроизведении получен конкретный дефект: корректный JSON содержал `answerCoverage=FULL`, а в `unresolvedTopics` модель записала незаполненные поля квалификации — `launch timing`, `primary goal`. `generate-natural-response.ts` отбрасывал весь ответ до семантической проверки из-за противоречия двух вспомогательных полей. Общая обратная связь repair не объясняла этот конфликт. Если восстановление тоже отклонялось, лаборатория скрывала сохранённый turn за `TEST_CHAT_LAB_FAILED (HTTP 500)`.

Исходные черновики двух пользовательских отказов не сохранялись, поэтому тождество причины каждого из них этому воспроизведённому дефекту не доказано. Доказаны успешные API-вызовы, отклонение результата pipeline и воспроизводимый конфликт coverage-метаданных.

## Исправление

- В компактной генерации удалены дублирующие `answerCoverage` и `unresolvedTopics`. Покрытие определяет уже существующая семантическая проверка по текущим вопросам, ответу и approved facts. Дополнительного LLM-вызова нет.
- Старые разделённые ответы с противоречивыми аннотациями доходят до этой проверки. Незнакомые бизнес-условия могут получить PARTIAL/UNKNOWN независимо от оптимистичной метки генератора. Пустые поля CRM не являются неизвестными бизнес-вопросами.
- Полезный ответ и допустимый следующий вопрос сохраняются. Проверки сумм, фактов, действий и actual unanswered requests остаются. Legacy-ответ без семантической проверки сохраняет прежнюю защиту от противоречивого coverage.
- В лаборатории сохранённое событие FAILED возвращается как результат тестового действия с историей и явным статусом ошибки. UI показывает причину и отсутствие отправленного ответа. Это не успех генерации: статус остаётся FAILED; сценарий останавливается, а не продолжает платные вызовы после такого результата. Неожиданная ошибка до сохранения события по-прежнему остаётся HTTP-ошибкой.
- Подключён существующий структурированный logger workflow. Секреты, reasoning и полные черновики постоянно не логируются. Временное диагностическое сохранение ответа удалено из кода.

## Проверки

Три новые проверки сначала RED, затем GREEN: сохранение полезного ответа при ошибочных coverage-заметках; независимое определение PARTIAL; сохранение истории и видимого FAILED вместо исключения лаборатории.

Полный suite: **692 passed**. Typecheck, lint и build — PASS.

Полный HTTP smoke через работающий dev-сервер `localhost:3001`, отдельная тестовая сессия, реальная Qwen и фиктивные внешние каналы:

1. «Я в Москве, на старт готов выделить 400 тысяч.» → HTTP 200, PROCESSED, LLM, ответ 468 символов, SENT.
2. «От вас то какая польза?» в том же диалоге → HTTP 200, PROCESSED, LLM, ответ 769 символов, SENT. Ответ объясняет пользу команды и её роли, затем предлагает уместное продолжение.

Проверялось наличие реального ответа и обработки, не только HTTP 200. Входящие и ответы сохранены в отдельной Test Chat Lab DB. Production не изменялся и не включался. Небольшой успешный smoke не доказывает отсутствие других вероятностных ошибок модели.
