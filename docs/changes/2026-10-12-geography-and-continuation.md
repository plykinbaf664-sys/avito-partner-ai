# География и продолжение коротких контекстных ответов

## Причина

Пять предыдущих живых проверок выявили расхождение: extraction сохранял `Химки, Подмосковье` целиком, deterministic geography не распознавал это значение и добавлял `REGION_NEEDS_REVIEW`, хотя ответ модели называл город подтверждённым. Формат `facts.city` не отделял населённый пункт от административных уточнений. Семантическая проверка ответа получала город, но не детерминированный статус доступности.

Два ответа были содержательными, но слабо продвигали разговор: рекомендация без дальнейшей помощи и подтверждение исправления после удаления повторного вопроса reviewer. Это недостаток выбора следующего шага, а не основание требовать вопрос в каждом ответе.

## Изменение

- Extraction семантически разрешает населённый пункт, региональные уточнения и альтернативы. Небольшой approved catalogue доступен как стабильный reference context. Неизвестный город не подменяется ближайшим поддерживаемым.
- `facts.city` имеет явный формат одного названия. Schema отклоняет разделители адресов/вариантов в structured output; существующий ограниченный retry просит модель разрешить населённый пункт. Код не разбирает фразы клиента и не выбирает город по substring/regex. При повторной ошибке остаётся консервативная degraded extraction.
- Merge сохраняет точное canonical approved name для уже распознанного alias; неизвестные названия не получают SUPPORTED.
- Brain и semantic reviewer получают один детерминированный `serviceabilityStatus` и `currentFacts.serviceability`, вычисленные из actual lead city. При NEEDS_REVIEW утверждать подтверждённую доступность запрещено; общий бизнес-вопрос по-прежнему можно объяснять с оговоркой.
- Prompt предлагает после исправления/неопределённости полезный новый шаг: релевантный ориентир, помощь с выбором или одну ещё не обсуждённую разрешённую тему. UNKNOWN не становится приказом задавать вопрос. NO_REPLY, manager-owned action, ответ без вопроса и semantic anti-repetition сохранены.
- Compact extraction явно различает формат накопленного профиля и разреженной delta; ошибки structured output не разрешают копировать весь профиль или придумывать поля/enum. Обновлены версии prompts. Дополнительных штатных LLM-вызовов нет.

## Регрессии и проверки

До исправления шесть новых assertions воспроизводили дефект формата, canonical persistence, неоднозначных альтернатив и отсутствующего serviceability в review payload. После исправления проходят.

Добавлены permanent unit cases, кеширование справочника с запретом customer context, настоящий двухходовый Test Chat Lab workflow с SQLite/fake channels и opt-in `scripts/eval-location-continuation.ts` с режимами live/replay. Исторические пять сценариев и их FAIL остаются в `docs/evals/2026-10-12-contextual-contributions.*`; они не переписаны под новую реализацию и не попадают в production model context.

Локально: **638 тестов / 49 файлов PASS**, typecheck/lint/build PASS. Первый полный прогон обнаружил INVALID_CACHE_FIELD из-за нового reference field; whitelist исправлен и защищён отдельными тестами, затем полный suite повторён успешно. Старые behavioral assertions не ослаблялись; обновлены только два ожидаемых номера promptVersion.

Два сфокусированных живых двухходовых Qwen-сценария, отдельные SQLite в памяти, fake Avito/Telegram, ручной анализ ответов и фактов:

1. География с регионом → контекстный вопрос о времени: **PASS**, Химки/SUPPORTED, ответ про 3–4 часа, новый полезный шаг, неизвестное доступное время не выдумано. 6 вызовов, 6581 µUSD.
2. Неизвестный масштаб → исправление города и срок запуска: **PASS**, масштаб не выдуман, рекомендация пилота, корректировка Москва → Волгоград, сохранены 350 000 ₽, расчётный ориентир обновлён 180 000 → 150 000 ₽, без повторных вопросов. 6 вызовов, 6131 µUSD.

Всего 12 SUCCESS calls к qwen/qwen3.8-flash, без retries, conversation repair или технических заглушек. Расчётный расход **$0.012712** по usage/config проекта, не сверка с биллингом. Успешные сценарии повторно через API не запускались. Живые отчёты содержат только синтетические разговоры и хранятся вне git; replay бесплатный.

## Ограничения и выпуск

Нельзя гарантировать безошибочность любых формулировок модели. Неопределённая география остаётся NEEDS_REVIEW, а форматная ошибка не должна превращаться в ложное подтверждение. Автоматическое массовое исправление старых production city values не выполняется. Canonical aliases нормализуются при следующем merge; неоднозначные старые значения требуют подтверждения/новых данных.

Выпуск использует отдельный Linux candidate с повторными typecheck/tests/lint/build, вручную проверенные live reports, recorded regression replays, read-only Avito coverage, backup и существующий guarded operational release с автоматическим rollback при критическом сбое. Env/provider/network/dependencies/schema DB не меняются. После переключения обязательны health/readiness, реальный production Qwen provider smoke, polling и один controlled replay E2E с fake channels. Точная revision, результаты серверных проверок и rollback manifest фиксируются внешним release helper; финальный статус сообщается после этих проверок.
